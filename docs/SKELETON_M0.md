# Milestone 0 — C++ Skeleton Contract

This is the concrete, binding file/class contract for the Milestone 0 skeleton. Charter Section 11.1 is the architecture; this document is the exact spelling so that files written in parallel agree. **Milestone 0 scope is "empty classes with a compiling build"**: every class exists with its properties, its public entry points, and doc comments, but gameplay logic bodies are stubs (`// TODO(M1): ...`) that at most log, clamp, or return defaults. The one exception is `URealmLadderLibrary`, whose generator is fully implemented at Milestone 0 (charter 6.1, Milestone 0 scope).

## Global rules for every source file
- UE 5.8 conventions: `#pragma once`; `#include "CoreMinimal.h"` first; the `*.generated.h` include is the **last** include in a header; `GENERATED_BODY()` in every UCLASS/USTRUCT; `UCLASS(...)` classes export with `ASCENSION_API` (runtime) or `ASCENSIONEDITOR_API` (editor).
- Use `TObjectPtr<T>` for UPROPERTY object pointers. Use `FGameplayTag`/`FGameplayTagContainer` for conditions, natures, states, systems (charter 11.2).
- Category strings for UPROPERTY/UFUNCTION: `"Ascension|<Area>"`.
- `EditDefaultsOnly`/`BlueprintReadOnly` on data-asset fields; `BlueprintCallable` on entry points designers/tests must drive; `BlueprintImplementableEvent`/`BlueprintNativeEvent` for presentation hooks.
- No `Tick` on `AQiWisp` (`PrimaryActorTick.bCanEverTick = false`).
- No hardcoded key checks anywhere (charter 8). No word "Law" as a progression term. No "mana"/"energy"/"MP" in any `FText`.
- Every numeric gameplay constant that a system will read at runtime is either a ladder-row field or a `UModifierStack` property name from `AscensionProps` (below), never a literal in a system. Milestone 0 only declares the names.
- Logging: `UE_LOG(LogAscension, ...)` from `AscensionLog.h`.
- Doc comment on every class explaining its charter section.
